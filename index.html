Executive Summary

La Cascada is a full-stack website built for La Cascada Restaurant & Bakery, an Italian restaurant and bakery based in Hurghada, Egypt — delivered by a three-person student team as a real-world engagement.

The system consists of three parts working together:

  • A public website covering the restaurant's brand, menu, gallery, and table reservation flow.
  • A Python (Flask) backend that serves the site, stores reservation and menu data, and exposes an admin dashboard for staff.
  • A Microsoft Power Automate flow that intercepts each new reservation and notifies the restaurant manager, who can accept or reject it without needing to check the site manually.

This document describes the site's structure, its features, the technical architecture, the reservation automation pipeline, and the roles each team member played in delivering it.

04

System Architecture

At a high level, the system follows a simple request/response flow between four actors: the website visitor, the Flask application, the Power Automate flow, and the restaurant manager.

VisitorSubmits reservation form
→
Flask backendValidates & stores request
→
Power AutomateNotifies manager
→
ManagerAccepts or rejects
→
SystemStatus updated

High-Level Flow

  1. A visitor browses the site and opens the Reservation page.
  2. The visitor submits the reservation form (name, contact details, date, time, and any special requests).
  3. The Flask backend validates and stores the reservation, then triggers the Power Automate flow.
  4. Power Automate formats the request and sends a notification to the restaurant manager.
  5. The manager accepts or rejects the reservation directly from the notification.
  6. The decision is reflected back in the system, and the reservation record is updated accordingly.

This removes the need for the manager to continuously monitor a dashboard — the reservation comes to them, and a single action closes the loop.

05

Website Walkthrough

Homepage

The homepage opens with a full-width hero section featuring the restaurant's signature imagery, tagline, and primary calls to action — "Reserve a Table" and "View Menu" — alongside a top navigation bar and a live open/closed status indicator.

Menu Page

The menu page presents dishes organized by category, each with a photo, name, description, and price. A footer note clarifies that all main dishes are served with rice and green salad, and the layout is built to extend easily as new categories are added.

About & Testimonials

The About page tells the restaurant's story and includes guest testimonials, reinforcing credibility before a visitor commits to a reservation. The page closes with a repeated call to action to view the menu or book a table.

Reservation Flow

The reservation page collects the guest's full name, email, phone number, preferred date and time, and any special requests. Client-side validation constrains dates to a sensible range before submission. The sidebar reinforces trust by showing the restaurant's address, phone number, social handle, and opening hours alongside the form.

Once submitted, the guest is shown a confirmation screen summarizing their booking details, with a note that the team will follow up to confirm — this is the point at which the Power Automate flow fires in the background.

Admin Dashboard

A password-protected admin area lists all incoming reservations in a sortable table — name, email, phone, date, time, and any special message — giving staff a full manual view of demand alongside the automated manager notifications. The same admin area includes menu management tools, so staff can update dishes and prices without touching code.

06

Reservation Automation with Power Automate

The standout feature of this project is that reservations are not just stored — they are actively routed to a human decision-maker in real time.

Why This Matters

A common failure point for small-restaurant booking systems is that reservation requests pile up in a dashboard nobody checks promptly. By pushing each request straight to the manager and letting them respond with a single accept/reject action, the system closes the gap between a guest's request and the restaurant's response.

How It Works

  1. The Flask backend captures the new reservation and calls a Power Automate trigger with the booking details.
  2. Power Automate packages the details into a clear, readable notification for the manager.
  3. The manager reviews the request and chooses to accept or reject it — from their phone or inbox, without opening the website.
  4. The response updates the reservation's status, so the restaurant's records and the guest's confirmation stay in sync.
This effectively turns Power Automate into the workflow layer between the website's data and the restaurant's real-world operations — a lightweight, no-extra-infrastructure way to bring human-in-the-loop approval to an automated system.

Future Improvements

Conclusion

La Cascada demonstrates a complete, practical web solution built for a real business: a polished public website backed by a genuinely useful automation layer.

Rather than treating automation as an add-on, the reservation-to-manager pipeline is the functional core of the project — turning a simple booking form into an operational tool the restaurant can use every day.
